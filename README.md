# wuwa-match3-bot

鳴潮「無音消除」三消活動的自動遊玩腳本。全程在本機運行：讀圖用本機顯卡做顏色閾值運算，決策用固定規則的代碼，不連網，也不使用任何 AI 模型或服務。PyTorch 在這裏只作為顯卡運算庫，沒有載入模型。

## 使用

1. 遊戲 client 區域設為 1280x720。
2. 雙擊 `run.bat`，在 UAC 提示按「是」（遊戲以系統管理員權限運行，滑鼠輸入也需要同等權限）。
3. 切回遊戲，自己揀關卡。

棋盤一出現就自動開打，打完回到等待狀態，下一關同樣自動開始。切走遊戲視窗時會暫停，切回來繼續。按 F8 結束。

只想看它會怎麼走、不實際操作：

```bash
python bot.py --dry
```

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `run.bat` | 雙擊啟動 |
| `bot.py` | 主循環：等待關卡、讀盤、出手 |
| `win.py` | 尋找遊戲視窗 |
| `capture.py` | PrintWindow 截圖 |
| `vision.py` | 在顯卡上辨識 8x7 棋盤與特殊棋，並判斷是否在關卡內 |
| `solver.py` | 模擬交換與連鎖，選分數最高的一步 |
| `inputs.py` | SendInput 滑鼠拖動 |
| `test_vision.py` | 用存檔畫面離線檢查辨識 |

## 已實測的遊戲行為

- 能量瓶會隨棋子下落；瓶子被消除後，遊戲會把棋盤上現有棋子變成新瓶子。
- 能量瓶和冰塊的「周圍」只算上下左右，斜角不算。
- 冰塊不動，但棋子會從旁繞過冰塊，填到冰塊下方；求解器的模擬不含這一點，只影響連鎖預測。
- 沙漏可以被拖動交換（遊戲的提示框會這樣走），但不參與配對；到底後加 2 回合。
- 連鎖結算期間的拖動會被遊戲忽略，而連鎖中途的停頓看起來像棋盤已靜止，所以每步都等回合數字跳動才走下一步。
- 沙漏到底時回合數會在連鎖中途跳動，偶爾令 bot 提早出手。這一下會被遊戲忽略，不扣回合，6 秒後自動重走，所以記錄裏可能見到同一步出現兩次。

## 除錯

`python bot.py --trace` 會在每步前印出棋盤：`H` 沙漏，`I` 冰塊，`E3` 剩 3 顆心的能量瓶，`U` 終極棋，`+` 十字棋，`*` 爆炸棋。

## 未驗證

- 爆炸或十字棋波及能量瓶和冰塊時如何計算：目前按相鄰規則處理。
- 能量瓶能否被拖動：目前一律不拖。
- 爆炸棋辨識：實戰讀到過，但未逐幀對照畫面核實。
- 棋盤尺寸不同的關卡、其他新棋子。新棋子可能被誤認成相近的棋子；遇到時請提供效果說明和截圖。

無法辨識的格子視為不可移動；超過 8 格認不出時會等待，不會出手。
