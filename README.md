# wuwa-match3-bot

《鸣潮》「无音消除」活动的自动游玩脚本。你自己选关，它负责把关打完。

全程在本机运行：截图、用本机显卡做颜色阈值判断、用固定规则的代码做决策、再模拟鼠标拖动。不联网，不调用任何 AI 模型或服务，也不读写游戏内存。PyTorch 在这里只是显卡运算库，没有加载任何模型。

> 非官方的第三方工具，与库洛游戏无关。自动化工具可能违反游戏用户协议，使用风险自负。

## 实测成绩

| 关卡类型 | 结果 |
| --- | --- |
| 分数关 | 中途接手，从 1720/5500 打到通关 |
| 能量瓶关 | 从 2/8 接手，5 步清完 |
| 沙漏关 | 开局 5 回合，靠沙漏加回合走了 13 步通关 |
| 无尽关 | 最终得分 26960（此前纪录 420）；人工打到 13/20 后接手，再走约 87 步 |

样本只有这几局，不代表每次都有同样的结果。

## 环境要求

- Windows，游戏窗口客户区设为 1280x720
- Python 3.10，依赖见 `requirements.txt`
- 有 CUDA 显卡时用显卡读图，没有时自动退回 CPU

```bash
pip install -r requirements.txt
```

`requirements.txt` 默认安装的 PyTorch 可能不带 CUDA。要用显卡，请按 PyTorch 官网的说明安装对应版本。

## 使用

1. 双击 `run.bat`，在 UAC 提示中选「是」。游戏以管理员权限运行，鼠标输入也需要同等权限。
2. 切回游戏，自己选关。

棋盘一出现就自动开打，打完回到等待状态，下一关同样自动开始。切走游戏窗口时暂停，切回来继续。按 F8 结束。

运行时游戏必须在前台，鼠标会被占用。

只看它会怎么走、不实际操作：

```bash
python bot.py --dry
```

## 工作原理

| 文件 | 作用 |
| --- | --- |
| `run.bat` | 双击启动 |
| `bot.py` | 主循环：等待关卡、读盘、出手 |
| `win.py` | 查找游戏窗口 |
| `capture.py` | 用 PrintWindow 截图 |
| `vision.py` | 在显卡上识别 8x7 棋盘和特殊棋子，并判断是否在关卡内 |
| `solver.py` | 模拟每一种交换和连锁，选评分最高的一步 |
| `inputs.py` | 用 SendInput 模拟鼠标拖动 |
| `test_solver.py` | 规则测试 |
| `test_vision.py` | 用保存的画面离线检查识别结果 |

支持的棋子：爆炸、十字、终极、能量瓶、冰块、沙漏，以及锁暝技能的连环和超连环。

## 实测得到的游戏行为

- 能量瓶会随棋子下落；瓶子被消除后，游戏会把现有棋子变成新瓶子。
- 能量瓶和冰块的「周围」只算上下左右，斜角不算。
- 冰块不动，但棋子会绕过冰块，填到冰块下方；求解器的模拟不包含这一点，只影响连锁预测。
- 沙漏可以被拖动交换，但不参与配对；到底后加 2 回合。
- 连锁结算期间的拖动会被游戏忽略，所以每步都等回合数字变化后才走下一步。
- 沙漏到底时回合数会在连锁中途变化，偶尔让 bot 提早出手。这一下会被游戏忽略，不扣回合，6 秒后自动重走，所以记录里可能出现同一步走两次。
- 无尽关的界面换成红色主题，所以关卡判断比对按钮文字形状，不比颜色。

## 调试

`python bot.py --trace` 会在每步前打印棋盘：`H` 沙漏，`I` 冰块，`E3` 剩 3 颗心的能量瓶，`U` 终极棋，`+` 十字棋，`*` 爆炸棋，棋子后的 `1`、`2`、`3` 是连环剩余次数。

## 尚未验证

- 爆炸或十字棋波及能量瓶和冰块时如何计算：目前按相邻规则处理。
- 能量瓶能否被拖动：目前一律不拖。
- 连环分组：游戏不显示哪些棋子同组，目前假定次数相同就是一组。
- 连环数字：受击闪光时可能把 ×3 读成 ×2，静止时是否也会读错尚未完全排除；误读只会让连锁预测有偏差，不会产生非法走法。
- 其他新棋子可能被误认成外观相近的棋子。

无法识别的格子视为不可移动；超过 8 格认不出时会等待，不会出手。
